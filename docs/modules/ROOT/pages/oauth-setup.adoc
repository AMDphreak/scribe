= OAuth and API access
:description: Configure GitHub or GitLab OAuth for Scribe when you use your own client ID and secret.
:page-toclevels: 3
:toc:

Scribe talks to **GitHub** and **GitLab** HTTP APIs so you can publish (commit and push) without running `git` or `gh` yourself for every action.
For that, the app uses **OAuth 2.0** in the system browser.
You only need the steps on this page if you **cannot** rely on the application’s default OAuth client or you are packaging Scribe for a different product identity.

== When you need a custom OAuth app

* You ship a **fork** or **white-label** build and must not use the default client ID.
* Your organization requires **its own** OAuth application with audited callback URLs and secrets rotation.
* You are **debugging** auth and want full control over the GitHub/GitLab application settings.

If you only use public GitHub/GitLab with the stock Scribe build, follow the in-app prompts first; come back here when you need to register your own app.

== Callback and localhost

Scribe expects the OAuth redirect to match the profile configuration.
Shipped profiles use a **localhost** callback on port **8080**:

* **Redirect / authorization callback:** `http://localhost:8080/callback`

Register that exact URL on the provider unless you change both the provider app *and* the matching profile fields in Scribe.

== GitHub

. Log in to GitHub.
. Open **Settings** → **Developer settings** → **OAuth Apps**.
. Select **New OAuth App**.
. Recommended fields:
   * **Application name** — `Scribe` or your product name.
   * **Homepage URL** — your project or company home (for example `https://github.com/AMDphreak/scribe`).
   * **Authorization callback URL** — `http://localhost:8080/callback`.
. Save the app, copy the **Client ID**, then **Generate a new client secret** and store the secret securely.

== GitLab

. Log in to GitLab.
. Open **Preferences** → **Applications** (or **User Settings** → **Applications**, depending on GitLab version).
. Create an application with:
   * **Name** — `Scribe` or your choice.
   * **Redirect URI** — `http://localhost:8080/callback`.
   * **Scopes** — enable `api`, `read_user`, and `write_repository` (or the minimum your workflow requires).
. Save and copy the **Application ID** (client ID) and **Secret**.

== Profiles (SDL)

Scribe reads **VCS profiles** from the `profiles/` directory next to the application (see the link:https://github.com/AMDphreak/scribe/tree/main/profiles[profiles] folder in the repository for examples such as `github.sdl` and `gitlab.sdl`).
Each file describes the host, OAuth endpoints, and optional `clientId` / `clientSecret` overrides.

Example fragment (replace placeholders with your credentials):

[source,sdl]
----
name "GitHub"
host "github.com"
clientId "YOUR_CLIENT_ID"
clientSecret "YOUR_CLIENT_SECRET"
----

The shipped profiles include `authUrl`, `tokenUrl`, and `apiUrl` for each host; keep those unless you use GitHub Enterprise or self-managed GitLab with different base URLs.

WARNING: Never commit real client secrets to a public repository. Use local overrides or a private config path for production secrets.

== After you change a profile

Restart Scribe or reload the site so profile discovery picks up changes.
Use **Settings** → **Profiles** in the app to confirm the host appears and connect the account again if the provider requires a new consent screen.
